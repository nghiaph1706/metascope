MetaScope PRD – Review & Decision Notes

File spec: specs/MetaScope_PRD_with_BE.md

Mục tiêu vòng lặp

Chạy review spec, sửa các điểm chặn triển khai, lặp lại cho đến khi không còn yêu cầu chỉnh sửa trọng yếu.

Quyết định đã áp dụng

  • Plan/giá: Guest/Basic/Premium được chuẩn hóa, Premium 99,000 VNĐ/tháng.
  • Single source of truth: Entitlement/quota đặt tại Section 5.5 với matrix rõ ràng.
  • Quota cứng: Basic Elo 5/tuần, Post-game 2/tuần; Premium Post-game 3/ngày.
  • Fair-use Premium: Elo 120 req/ngày/user, Matchup Coach 60 req/ngày/user.
  • Atomic quota: check+increment bằng Redis script một bước; có compensation rollback theo idempotency key.
  • Auth SSoT: Firebase UID là nguồn identity duy nhất.
  • Riot ID canonical: domain model dùng gameName#tagLine, URL dùng percent-encoding.
  • API đồng bộ: bổ sung endpoint /api/v1/meta/patch-notes/:version.
  • Route đồng bộ: UI dùng /tools/post-game-analysis nhất quán với API.
  • Data architecture: PostgreSQL + Redis (TCP) + OpenSearch read model theo phase rollout.
  • Redis/BullMQ: tách rõ env REDIS_TCP_* (bắt buộc) và Upstash REST (optional).

Tại sao chọn các phương án này

  • Giảm mâu thuẫn giữa mô tả sản phẩm và contract kỹ thuật để tránh bug entitlement/quota khi build.
  • Ưu tiên tính đúng đắn giao dịch (payment/quota) bằng mô hình source-of-truth rõ ràng.
  • Bảo vệ chi phí AI bằng fair-use số hóa, thay vì mô tả mơ hồ.
  • Tăng khả năng vận hành trên 1 VPS bằng rollout theo phase, không ép full complexity ngay MVP.
  • Giữ khả năng mở rộng sau này (OpenSearch alias/version, idempotency, compensation).

Đợt chỉnh sửa cuối sau review xác nhận

  • Payment contract: bỏ userId khỏi body create-payment-link, backend lấy user từ Bearer token.
  • Quota wording canonical: làm rõ Premium Post-Game là hard cap 3/ngày; Elo/Matchup là unlimited theo fair-use soft-limit.
  • OpenSearch canonical: nhấn mạnh code production chỉ query alias metascope_*_current.
